# ADR 0001 — Render topology diagrams on demand, not at build time

**Status:** Implemented · 2026-09-08
**Scope:** `public/media/library/outputs/estate-topology/**`, the capability circuit surface, `CircuitProjection`
**Supersedes:** the prebuilt-artifact delivery introduced in `f3f3acc` / `d0af66d`

---

## 1. Context

The capability circuit workbench is currently delivered as **prebuilt static artifacts**: one
`index.html` per scenario, plus one `n-<id>.js` file per topology view, generated by
`compile_estate_topology.py` in the content lab and committed into `public/media/` in this
repository. The website embeds them through a sandboxed `<iframe>`.

This delivered correctly and passes validation. The graphs it renders are real, source-backed and
far richer than the boundary lens they sit on top of. The problem is not the diagrams — it is how
they reach the browser.

### 1.1 Measured cost

`public/media` is **207 MB across 3,591 files**, all committed to git (`.git` is now 79 MB).
Of that, `estate-topology` alone is **166 MB**: 810 `index.html`, 217 `catalog.js` and
**1,578 `n-*.js` view files** averaging ~100 KB each. Only **78 files in the whole
`public/media` tree are images**; the rest is HTML and JavaScript.

Composition of the 157 MB of view JavaScript, measured over a deterministic 150-file sample
spanning the corpus:

| Field | Share of bytes |
| --- | --- |
| `svg` — a pre-rendered SVG string | **47.7%** |
| `nodes` — source graph data | 22.9% |
| `edges` — source graph data | 21.1% |
| `layout` — box coordinates | 1.3% |

**Approximately half of the payload is a cached render of the other half.** A single view in
`admit-canonical-circuit-blueprint` is 1.25 MB: 653 KB of SVG on top of the 504 KB of nodes and
edges that SVG was drawn from.

### 1.2 The stored SVG is 91% recomputable markup

Each view carries `layout.boxes` — an exact `[x, y, width, height]` per node — alongside
`layout.width` / `layout.height`. Across 200 sampled views, **`layout.boxes` covers every node in
200 of them**. Material textures are a pure function of `node.kind`: across 250 sampled views,
**8,374 texture references matched their node with 0 unmatched and 0 conflicts**, resolving to
exactly 10 textures for 10 node kinds.

One part is *not* derivable. [`estate_topology_render.py`](../../../content-creation-mission/scripts/estate_topology_render.py)
lays the graph out with **Graphviz** (`splines='spline'`), so the bezier control points of each
route are *measured* by the layout engine, and `layout` stores only node boxes — not the route
splines. Those curves exist solely inside the SVG string. Any claim that the stored SVG is fully
reconstructible from the retained fields is false, and an earlier draft of this ADR said so
incorrectly.

Measuring what that actually costs, over a 150-file sample:

| Portion of the stored `svg` | Share |
| --- | --- |
| Route path `d=` geometry — **must be retained** | 4.9% |
| Edge label positions — must be retained | ~4.2% |
| **Rects, texture `<image>`s, `<text>`, `<title>`, `<desc>`, roles, attributes — recomputable** | **90.9%** |

So the correct framing is not "the SVG is redundant" but: **the SVG is 91% rendered markup wrapped
around 9% of irreplaceable layout geometry.** Retaining the geometry and discarding the markup
removes 10.14 MB of every 11.15 MB of SVG in the sample — extrapolating to roughly **68 MB across
the corpus** — while preserving Graphviz's exact routing.

Graphviz stays where it belongs: a build-time layout engine whose output is expensive to compute
and cheap to store. What gets dropped is the *rendering* of that layout, which is cheap to compute
and expensive to store.

### 1.3 Cost is incurred repeatedly

[`Dockerfile`](../../Dockerfile) does `COPY . .` in the build stage and
`COPY --from=build /app/public ./public` in the runtime stage. The full 207 MB therefore lands in
the **runtime container image** on every deploy, and is checked out on every CI run. The cost is
paid on clone, on build, on image push, on image pull, and on container start — for bytes that a
renderer could produce in milliseconds.

### 1.4 Governance consequence

This is the more serious half of the problem. The view data ships as
`window.ESTATE_TOPOLOGY_VIEW = {…}` browser globals inside an iframe, which means:

- It never passes through `CircuitProjection` or any other contract in [`contracts/`](../../contracts/estate.ts).
- It carries no graph digest, no pinned renderer version and no SCL version — the identifiers
  §12.2 requires on every published circuit.
- Its node and edge vocabulary — `provider-port`, `provider`, `provider-binding`, `decision`,
  `termination`, `selection`, `recurrence` — exists **only** inside the artifacts. The site's own
  contract still describes 824 four-node boundary circuits with zero provider slots.
- Accessibility, theming and CSS stop at the sandbox boundary. The parent page cannot enforce or
  test the keyboard selection, node naming and inspector focus behavior §6.6 and §12.4 require.

The result is that the site's most prominent view is its least governed one, in a codebase whose
entire premise is that published claims are validated against contracts.

### 1.5 What legitimately motivated pre-rendering

The largest compiled graph contains **1,493 nodes**, and the corpus renders tens of thousands of
component occurrences. Rendering that per request is genuinely expensive, and pre-rendering is a
reasonable first instinct.

It is the wrong remedy for two reasons. First, it does not address the cost — it relocates it from
render time to storage, transfer and image size, where it is paid more often. Second, §12.4 already
rules that large graphs "load at capability/scenario scope and use drill-down rather than rendering
the entire estate": a 1,493-node diagram is not readable by a person, so shipping it whole is not a
feature worth optimising for.

## 2. Decision

**Topology diagrams are rendered on demand from validated graph data. The rendered SVG is never
stored, committed or delivered as a source artifact.**

### 2.0 Binding constraint: this decision does not change the user experience

This is an efficiency and governance decision about **how bytes are delivered**. It is not a
licence to change what the workbench does. The two are orthogonal: rendering from data instead of
shipping markup has no bearing on which controls exist, and no feature may be dropped in its name.

Concretely, every capability of the compiled workbench is preserved: grouped source-view selection
with per-view counts, the material/base appearance toggle, fit / read-at-100% / zoom with a
readout, SVG export, component search, the outline with click-to-reveal, the full source inspector
(responsibility, identity, facts, SHA-256 and source pointer), declared-route stepping, the
findings line, and illustrative flow with its speed, follow, next-step and reset controls.

**A first implementation of this ADR violated that constraint.** It ported the renderer, shipped
it as though it were the workbench, and silently dropped flow playback, the zoom and fit controls,
the material/base toggle, SVG export, the search box, route stepping and most of the inspector.
Those were restored, and this section exists so the constraint is a stated part of the decision
rather than an assumption. Any future delivery change under this ADR is measured against feature
parity first and byte count second.

The visuals are product surface, not implementation detail. A byte saving that costs a control is
not a saving.

Concretely:

1. **Retain the layout, drop the rendered markup.** `layout` is extended to carry the Graphviz
   route splines and edge label positions that today exist only inside the SVG string; the `svg`
   field is then dropped. The website renderer produces SVG from `nodes`, `edges` and that
   extended `layout`.
2. **Bring the graph into the contract.** A `TopologyView` contract carries the node and edge
   vocabulary, layout, source provenance and findings, validated on read like every other
   published record, and pinned by digest in the publication manifest.
3. **Retire the iframe.** The workbench becomes a server-rendered React component using the site's
   own design tokens, so keyboard interaction, node naming, theming and the text outline are the
   parent document's responsibility and are testable.

The SQL bundles remain the source of truth and are unaffected. This decision changes only what is
*delivered*, which the audit already classifies as a rebuildable delivery artifact.

### 2.1 Explicitly not decided here

- **Whether to keep material textures.** The `.webp` texture references are real assets, not
  derived data, and stay.
- **Where remaining media is hosted.** Moving `public/media` to hash-addressed CDN delivery under
  §11.5 is a separate decision; this ADR reduces what would need moving.
- **The image backfill.** 20 of ~2,600 entity artwork requirements are `READY`. Unrelated to this
  change and still open.

## 3. Consequences

### 3.1 Expected

- **~68 MB removed** from the repository, every container image and every CI checkout, with no
  change in what a visitor sees. (Measured after the change, not estimated — see §4.)
- The graph vocabulary that already exists in the artifacts — provider ports, bindings, decisions,
  terminations — becomes visible to the contract, the tests and the inspector for the first time.
  The site can then honestly describe what it renders, which it currently cannot.
- Circuit rendering gains graph digests and pinned renderer versions, closing the §12.2 gap.
- Accessibility becomes enforceable and testable in the parent document.

### 3.2 Costs accepted

- **Server render cost per view.** Mitigated by rendering at scenario scope with drill-down, and by
  caching on a digest key at the edge if a specific view proves expensive. This is a caching
  decision, not a storage decision.
- **Interaction parity is a porting job.** `viewer.js` is 452 lines covering inspect, outline, fit,
  trace planning and the silver-ball player. Until each behavior is ported it must be reported as
  unported rather than assumed — see §4.
- **The compiler must change.** `estate_topology_render.py` in the content lab still emits `svg`
  and does not persist route splines into `layout`. Until it does both, the website ingest
  recovers the geometry by parsing the SVG once, at build time, and strips the field.

### 3.3 Risks

- **Visual regression.** The renderer must reproduce the stored geometry exactly. Mitigated by
  comparing rendered node and route identities and coordinates against the stored SVG for the same
  view before the stored copy is removed.
- **Large-graph performance on first load.** Mitigated by scenario-scope rendering; measured rather
  than assumed.

---

## 4. Honesty conditions

Per §8.3 and the honesty invariants in [`architecture.md`](../architecture.md), this migration may
not silently reduce capability:

- Any `viewer.js` behavior not yet ported is listed as unported in
  [`visual-integration-audit.md`](../visual-integration-audit.md). Flow playback in particular is
  not claimed until it demonstrably traverses the same routes as the artifact player.
- Removing the stored SVG does not change any evidence claim. It is a delivery change, and the
  publication continues to validate node and route identities against the graph — now against the
  contract record rather than against a rendered string.
- Byte counts quoted in documentation are re-measured after the change, not estimated.

## 5. Implementation sequence

| Step | Change | Verifiable by |
| --- | --- | --- |
| 1 | `TopologyView` contract + ingest that extracts route geometry, strips `svg`, validates the graph | Contract tests; ingest reports stripped bytes |
| 2 | Server-rendered SVG from `nodes` / `edges` / `layout` | Rendered node and route identities match the stored SVG for the same view |
| 3 | Capability page renders it; iframe retired | Page HTML contains the graph server-side; no `<iframe>` |
| 4 | Stop exporting the compiled artifacts from SQL and prune them | Re-measured repository and image size |

Step 1 and 2 are reversible; step 4 is the point of no return and ran only after step 2 verified.

---

## 6. Implementation result

All four steps are complete and measured.

**Parity, verified before deletion.** `scripts/verify-topology-parity.ts` compared the on-demand
render against the stored SVG for **all 1,578 views**: identity and geometry parity held for every
one — same components, same routes, same spline paths, same measured boxes, none invented and none
dropped. This was the gate for step 4 and it ran to completion, not on a sample.

**Delivery.**

| | Before | After |
| --- | --- | --- |
| `public/media` | 207 MB / 3,591 files | **41 MB / 171 files** |
| Published media artifacts | 3,589 | 171 |
| Compiled topology delivered | 157 MB of HTML + JS | none |
| Topology as validated data | none | 77 MB in `generated/topology` |

The ingest discarded **69.2 MB of rendered markup** while retaining 6.7 MB of Graphviz route
geometry. Net, ~166 MB of delivery left the repository and the runtime container image, and what
remains is data under contract rather than markup.

**Governance.** 217 bundles carrying **1,578 views, 41,200 components and 40,752 routes** now
validate against `contracts/topology.ts` on every read. Each view carries a `graphDigest`, and the
release manifest pins the whole bundle set — so an altered bundle fails the read instead of
rendering. The vocabulary the iframe hid (`provider-port`, `provider-binding`, `decision`,
`termination`, `unresolved`) is now in the contract and in the inspector.

**Two corrections found while implementing.** The contract initially required source fields that
only capsule-entry provenance carries; SQL selected-blueprint sources carry `definitionPk` /
`definitionDigest` instead, and both shapes are now preserved as they are. And the compiler emits an
`unresolved` node kind that it paints with rejection styling — it is now rendered as itself and
labelled "Unresolved reference", so it cannot read as a declared rejection.

### 6.1 Feature parity

The full workbench is ported. Illustrative flow is driven by `plan-trace.ts` and
`use-trace-player.ts`: the planner is a direct port of the original `planTrace`, and
`tests/trace-parity.test.ts` compares the two on real published graphs — **identical wave plans,
wave for wave**, including branch order, convergence waiting and the provider-binding timing fix
from `11e1c05`. The sphere follows the same compiled route paths through `getPointAtLength`.

Restored alongside it: grouped view selection with counts, material/base toggle, fit,
read-at-100%, zoom with readout, SVG export (material plates stripped, as the original did),
component search, outline click-to-reveal, declared-route stepping with its convergence and
fan-out guidance, and the inspector's facts, SHA-256 and source pointer.

The one deliberate difference: the workbench is now part of the page rather than an iframe, so its
controls use the site's own tokens and its components are elements the parent document can name,
focus and test.
